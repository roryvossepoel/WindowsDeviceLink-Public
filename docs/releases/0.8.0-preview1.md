# WindowsDeviceLink 0.8.0-preview1

This preview adds a compact full-Windows operator GUI on top of the existing WindowsDeviceLink lifecycle cmdlets.

## What's new

### Show-WindowsDeviceLink

New public command:

```powershell
Show-WindowsDeviceLink
```

The GUI provides a single-screen operator workflow for:

- local DeviceLink and firmware state;
- source-tenant correlation;
- tenant-side Device Association status;
- tenant selection by friendly name;
- DeviceLink CSV export;
- pre-association;
- full association;
- cloud-only offboarding;
- local-only offboarding;
- full DeviceLink offboarding;
- live activity output.

The GUI is currently supported on full Windows. WinPE remains a command-line workflow.

### Authentication selection

Interactive authentication is the default:

```powershell
Show-WindowsDeviceLink
```

Alternative supported methods can be selected explicitly:

```powershell
Show-WindowsDeviceLink -Method DeviceCode
```

App-only and token-based methods use the same existing credential parameters as the underlying WindowsDeviceLink online cmdlets.

### Friendly tenant selector

Administrators can provide a friendly tenant list:

```powershell
Show-WindowsDeviceLink `
    -Tenants @{
        'Management' = '11111111-1111-1111-1111-111111111111'
        'Contoso'    = '22222222-2222-2222-2222-222222222222'
    }
```

The selected tenant is passed as the explicit tenant context for supported online actions.

### Onboarding actions

The GUI exposes two distinct onboarding operations:

- **Pre-associate** — creates only the tenant-side Device Association pre-association.
- **Full associate** — uses `Initialize-WindowsDeviceLink -CompleteAssociation` to ensure pre-association and complete native device-side association.

The full-association progress stream is shown live in the Activity area.

### Offboarding actions

The GUI keeps cloud and local state explicit:

- **Cloud** — removes only the tenant-side Device Association.
- **Local** — resets only the known local DeviceLink UEFI variables.
- **Full** — verifies cloud state, removes the cloud association when present, and resets local DeviceLink state only after the cloud state is known.

Full offboarding fails closed when cloud association state is indeterminate.

### Local/cloud state synchronization

After pre-association and full association, the GUI refreshes both local and cloud state so stale UI values are not retained.

### Operator safety

During a running operation:

- all lifecycle/action buttons are disabled;
- the tenant selector is disabled;
- the form cannot be closed through the normal close action;
- a busy progress indicator is shown;
- output continues to stream to the Activity view and the PowerShell host.

The GUI delegates lifecycle operations to existing WindowsDeviceLink cmdlets. It does not implement separate Graph or firmware mutation logic.

### UI polish

The dashboard includes:

- module version and Preview status in the window title;
- compact Windows 11-style cards;
- friendly state labels such as `Complete association`;
- concise local source labels with technical values preserved in tooltips;
- consistent `Unavailable` values;
- ISO 8601 date/time rendering in Activity output where possible;
- activity clearing;
- conditional outer scrolling for lower-height displays.

## Validation

The GUI was exercised on physical AMD64 Windows 11 hardware.

Validated flows include:

- local status refresh;
- online cloud lookup;
- CSV export;
- pre-association;
- full association to `4/4`;
- post-association local/cloud state synchronization;
- cloud-only offboarding;
- local-only offboarding;
- full offboarding safety behavior;
- tenant selection;
- busy-state interaction blocking.

The hardware-independent `Gui-Contract-Validation.ps1` test locks the public GUI contract and is included in CI and staged Gallery-package validation.

## Existing 0.7 capabilities retained

This release also includes the local source-tenant discovery introduced in 0.7:

```powershell
Get-WindowsDeviceLinkLocalAssociation
```

Local registry and Association JWT tenant evidence remains explicitly correlated and fail-closed on conflict.

## Remaining preview work

- live Azure validation of the multitenant reconcile New / Update / Move workflow tracked in issue #33;
- trusted code signing;
- ARM64 research/validation;
- continued validation across additional Windows builds and hardware.

WindowsDeviceLink remains preview / proof-of-concept software. Native DeviceLink completion uses undocumented Windows Runtime interfaces, and Device Association cloud operations use Microsoft Graph beta endpoints.
