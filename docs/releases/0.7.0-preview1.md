# WindowsDeviceLink 0.7.0-preview1

This preview adds local source-tenant discovery and turns the research from issue #34 into a supported public, read-only capability.

## What's new

### Local source-tenant discovery

New public command:

```powershell
Get-WindowsDeviceLinkLocalAssociation
```

The command determines the expected source tenant from local DeviceLink metadata without Microsoft Graph authentication.

It correlates:

- the exact current-LinkId registry value under `HKLM\SOFTWARE\Microsoft\Provisioning\AutopilotSettings\<LinkId>_TenantIdHint`;
- the `tenantId` claim in `DeviceLinkJwtCompressed` when the Association JWT is present.

The raw JWT, signature, TPM material and unrelated claims are not returned.

### Explicit local trust levels

The command exposes where the tenant ID came from and how strongly the local sources agree:

```text
CorrelatedLocalSources
LocalRegistryHint
StructurallyObservedJwtClaim
Conflict
Unavailable
```

When registry and JWT tenant identifiers disagree, WindowsDeviceLink fails closed and does not select a TenantId.

### Historical registry hints are ignored safely

Live testing showed that old `<LinkId>_TenantIdHint` and `_DiscoveryUrl` values can remain after local DeviceLink firmware reset.

WindowsDeviceLink therefore never selects an arbitrary historical hint. Only a registry value whose prefix exactly matches the **current** UEFI `DeviceLinkId` is eligible.

### Validated tenant-hint lifecycle

Physical-device testing established this lifecycle:

```text
0/4
-> no current DeviceLinkId
-> historical hints may remain
-> no tenant selected

Get-WindowsDeviceLink
-> new 2/4 base identity
-> no current-LinkId TenantIdHint yet

Graph preassociation
-> still 2/4
-> still no local TenantIdHint

Test-WindowsDeviceLinkDiscovery
-> still 2/4
-> writes <current LinkId>_TenantIdHint and _DiscoveryUrl
-> tenant becomes locally discoverable

native completion
-> 4/4
-> DeviceLinkJwtCompressed appears
-> JWT tenantId can be correlated with the registry hint
```

### Cloud deletion does not remove local tenant evidence

After deleting the tenant-side Device Association record, an associated device retained:

- local firmware state `4/4`;
- the current-LinkId registry `TenantIdHint`;
- `DeviceLinkJwtCompressed`;
- the JWT `tenantId`.

This further validates the separation between cloud Device Association state and local DeviceLink tenant affinity.

### Multitenant workflow simplification

Local source-tenant discovery simplifies caller-side intent construction:

```text
Get-WindowsDeviceLinkLocalAssociation
-> expected source tenant
-> operator/workflow chooses target tenant
-> backend performs fresh cloud verification
-> backend derives New / Update / Move
```

Tenant-wide lookup is now primarily a fallback and verification path instead of the default way to discover the source tenant.

The backend still performs fresh tenant-side verification before mutation so local/stale metadata cannot directly authorize a Move.

## JWT signature trust boundary

The observed Association JWT uses RS256 and exposes `kid` / `x5t` signing-key identifiers.

Research with both WindowsDeviceLink tooling and an independent DeviceLink validation script did not locate a supported published signing-key set for the observed `DeviceTag_<guid>` issuer.

WindowsDeviceLink therefore reports:

```text
SignatureValidation : NotPerformed
```

and does not claim cryptographic verification of the JWT.

The tenant ID remains useful as locally observed and, when both sources are present, correlated local state.

## Validation

The complete hardware-independent regression suite passed for the 0.7.0 candidate.

Coverage includes:

- public module/export contract;
- local tenant-correlation precedence and fail-closed behavior;
- firmware safety;
- Association JWT parsing;
- authentication/security boundaries;
- Graph paging/response/failure handling;
- Device Association API contract;
- health and repair planning;
- native DeviceLinkManager wrapper contract;
- Azure Function / Automation backend contracts;
- webhook sanitization;
- WinPE validation runner.

Live physical validation was performed on AMD64 Windows 11, including:

- `0/4` local reset state;
- new `2/4` base identity;
- tenant-side preassociation;
- native discovery;
- current-LinkId TenantIdHint creation;
- `4/4` association;
- local registry/JWT tenant correlation;
- cloud-side association deletion while local tenant metadata remained present.

## Notes

WindowsDeviceLink remains preview / proof-of-concept software.

Native DeviceLink completion uses undocumented Windows Runtime interfaces, and Device Association cloud operations use Microsoft Graph beta endpoints. These interfaces can change without notice.

Trusted code signing remains open work. The initial SignPath Foundation application was reviewed but not approved because the project does not yet have enough external adoption/visibility signals.
