# WindowsDeviceLink 0.10.1-preview1

This focused GUI preview separates tenant context from Device Association actions.

## Target tenant workflow

The operator dashboard now presents **Target tenant** as its own action row above
**Device association**:

- Direct interactive and device-code modes expose **Sign in** and show the
  tenant established by the authenticated session.
- Direct catalog mode keeps tenant selection and sign-in together in the same row.
- Backend mode presents its authoritative tenant selector in the same location without
  device-side sign-in.
- **Sign in** changes to **Sign out** after authentication. Signing out clears the
  in-memory authentication context and unlocks catalog-based target selection.
- A catalog-based target selector remains locked during a delegated session, and the
  authenticated tenant must match the selected target tenant.
- The Connection card shows the delegated account after sign-in and immediately updates
  the tenant scope. A configured catalog name is preferred; otherwise the tenant ID is
  shown without requiring another Graph permission or lookup.
- Delegated sign-in now exposes an explicit waiting state, updates the Target tenant
  guidance after authentication, and uses the available row width to show the complete
  tenant ID whenever the window size permits.

The separate **Device association** row contains only **Pre-associate** and
**Associate**. Interactive association actions remain disabled until sign-in has
established a valid target tenant. **Status** now contains only cloud and local refresh
actions.

Device Preparation profile selection is intentionally out of scope for this release.
The new Target tenant row provides a logical location for that separately tracked
future capability without coupling it to the association buttons.

## Compatibility

No public cmdlet, parameter, backend API, or association-state contract changed in this
release. The Function backend remains compatible with the 0.10.0 module contract.
