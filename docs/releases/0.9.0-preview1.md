# WindowsDeviceLink 0.9.0-preview1

This preview focuses on making the operator experience simpler, more consistent and better validated across full Windows and AMD64 Windows PE.

## Highlights

### Operator GUI hardening

`Show-WindowsDeviceLink` has been substantially refined:

- Windows 11 defaults to `Interactive` authentication.
- Windows PE defaults to `DeviceCode`.
- Windows PE can use an administrator-supplied runtime with `-WindowsManagementServicePath`.
- CSV export now uses a WinPE-safe path picker instead of relying on the shell folder browser.
- cloud association state labels are normalized to `Not checked`, `Pre-associated`, `Associated` and `Not associated`;
- local tenant-source labels are simplified to `Registry + JWT`, `Registry`, `JWT`, `Conflict` or `Unavailable`;
- action buttons are capability/state aware;
- Activity output is more compact while preserving authentication and lifecycle progress;
- cloud/local/full offboarding paths were validated for success, no-op and stale-state scenarios;
- missing cloud association during cloud-only offboarding is presented as an informational no-op instead of a red error.

### Association terminology

The explicit association opt-in introduced during the preview series is now written as:

```powershell
Initialize-WindowsDeviceLink -Associate
```

The earlier preview spellings were subsequently superseded by this Microsoft-aligned term.

Initialization result properties now use:

- `AssociationRequested`
- `AssociationResult`
- `AssociationDetails`

The low-level cmdlet `Complete-WindowsDeviceLinkAssociation` remains because "Complete" is the verb describing that explicit device-side operation.

> This is a preview API rename. Scripts should use `-Associate`.

### Tenant selector sources

The GUI tenant selector can now be populated in three ways:

```powershell
Show-WindowsDeviceLink -Tenants @{
    'Tenant Alpha' = '11111111-1111-1111-1111-111111111111'
    'Tenant Beta' = '22222222-2222-2222-2222-222222222222'
}
```

```powershell
Show-WindowsDeviceLink -TenantsPath 'E:\Config\tenants.json'
```

```powershell
Show-WindowsDeviceLink -TenantsUri 'https://config.example.com/windowsdevicelink/tenants.json'
```

The JSON schema is a simple friendly-name-to-tenant-GUID map. Precedence is `TenantsUri -> TenantsPath -> Tenants`, so explicit `-Tenants` values win.

### Full Windows lifecycle validation

A physical Surface Laptop 3 was used for a clean end-to-end full-Windows lifecycle:

```text
2/4 Base identity
-> pre-association
-> native discovery
-> current-LinkId tenant hint
-> association
-> 4/4 firmware + Association JWT
-> cloud associated
-> correlated local tenant sources
```

Validated edge cases include:

- association idempotency;
- cloud-only offboarding from 4/4;
- local-only offboarding while cloud state remains;
- full offboarding;
- cloud missing while local firmware remains 4/4;
- fail-closed pre-registration/association behavior for that inconsistent state;
- local reset/rematerialization to a new 2/4 base identity.

### Windows PE validation

On AMD64 Windows PE the GUI has been validated for:

- local state inspection;
- DeviceCode authentication;
- online cloud lookup;
- pre-association;
- cloud/local/full offboarding;
- DeviceLink CSV export;
- explicit `Windows.Management.Service.dll` runtime selection.

Association remains disabled in Windows PE. The standard workflow is to pre-associate in WinPE and let full Windows/OOBE complete Device Association.

### Authentication improvements

GUI DeviceCode flows were tightened so multi-step operations reuse one acquired token where appropriate.

Validated examples include:

- pre-association with one DeviceCode sign-in;
- full offboarding with one DeviceCode sign-in reused for verification and removal.

### Status and serial-number resilience

`Get-WindowsDeviceLinkStatus` can fall back to the BIOS serial number when DeviceLink runtime data does not expose a serial number, improving online lookup robustness.
