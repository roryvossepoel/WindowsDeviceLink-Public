# WindowsDeviceLink 0.10.0-preview1

This consolidation preview formalizes two execution routes without splitting the module:

- **Direct mode** talks directly to Microsoft Graph. Interactive and DeviceCode flows do
  not require TenantId; the sign-in context chooses the tenant. An explicit tenant or a
  friendly-name JSON catalog remains available when an operator manages several tenants.
- **Backend mode** uses the optional Azure Function backend for an authenticated tenant
  catalog, complete multitenant lookup, and guarded New, no-op, or Move orchestration.

## Unified assignment

`Set-WindowsDeviceLinkTenant` now supports both routes. Direct mode reuses the safe
initializer and one authentication context. Backend mode retains full pre/post-state
verification and never silently falls back to Direct mode.

Assignment results expose `OperationMode`, `Decision`, `ReasonCode`, `Changed`,
`RetrySafe`, and `RecommendedAction` alongside tenant and association details.

## Operator GUI

The unified operator view exposes Device, Connection, Local association, and Cloud
association in a compact two-by-two layout, with all actions below. In Backend mode, the operator selects a target tenant and
**Register device** performs lookup, decision, identity renewal, registration, and
verification as one workflow. Direct mode displays whether the tenant is determined by
sign-in or selected explicitly. Backend mode requires an explicit target from the
authenticated Function catalog. Diagnostic and lifecycle controls remain available in
the same view.

The GUI automatically loads local and cloud state when it opens. Its status cards use
subtle, non-exclusive color cues while retaining explicit text labels. The packaged
application icon and WinPE-safe font fallback do not depend on organization branding.

## Validation

The Backend-mode workflow was validated from Windows PE with a real device across two
configured tenants. New/no-op and verified Move behavior were exercised, including a
successful Kerkrade-to-Landgraaf reassignment after local identity renewal. Automated
contract, backend-runtime, tenant-assignment, authentication, transport, and safety
regressions remain part of CI.

## Backend compatibility

The tenant-catalog endpoint now returns API version, minimum module version, and
capabilities. Version or capability mismatches fail closed before any cloud mutation.

## Tenant catalogs

`Get-WindowsDeviceLinkTenantCatalog` reads a local JSON file, trusted HTTPS JSON, or
hashtable. A catalog is an address book only: it does not provide cross-tenant lookup or
Move capability.
